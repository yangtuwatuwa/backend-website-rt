# 🪙 Bab 8: Sistem Keuangan, IPL (Iuran Bulanan), & Uang Kas RT

Bab ini memuat panduan lengkap integrasi kontrak API sistem keuangan RT terpadu (*Single Source of Truth*), yang membagi pencatatan keuangan menjadi:
1. **IPL (Iuran Pengelolaan Lingkungan)**: Tagihan bulanan berbasis periode tagihan (`bill_periods` ➡️ `bills` ➡️ `payments` + `payment_bill_links`), dengan snapshot nominal & tenggat, mendukung **pembayaran rapel** (banyak bulan sekaligus dalam satu transaksi transfer/cash).
2. **Uang Kas RT (Insidental & Sosial)**: Iuran sukarela atau sumbangan insidental (`kas_contributions`), seperti santunan kematian, iuran kerja bakti, atau kegiatan 17 Agustusan, dengan format verifikasi konsisten.
3. **Buku Kas Besar (Financial Ledger)**: Pencatatan otomatis setiap dana masuk/keluar ke tabel `financial_ledger`.
4. **Dashboard Tracking & Landing Page Stats**: Pelacakan kepatuhan warga dan transparansi arus kas publik.

---

## 🧐 Perbedaan Sistem IPL vs Uang Kas RT

| Kriteria | IPL (Iuran Pengelolaan Lingkungan) | Uang Kas RT (Insidental / Sosial) |
| :--- | :--- | :--- |
| **Sifat Iuran** | Wajib bulanan berkala | Sukarela / Insidental per kegiatan |
| **Alur Tagihan** | `bill_periods` ➡️ `bills` ➡️ `payments` | `kas_contributions` (tanpa periode tagihan) |
| **Dukungan Rapel** | **Ya** (Bisa bayar 1 atau banyak bulan via `billIds`) | Tidak berlaku (bersifat per transaksi/kegiatan) |
| **Status Tagihan (Bill)** | `unpaid`, `waiting_verification`, `paid`, `overdue` (dinamis), `exempt` | *N/A* (tidak menggunakan tabel `bills`) |
| **Status Pembayaran** | `pending`, `approved`, `rejected` | `pending`, `approved`, `rejected` |
| **Buku Kas (Ledger)** | Tercatat otomatis saat pembayaran di-*approve* | Tercatat otomatis saat iuran di-*approve* |

### C. Membayar Tagihan IPL (Mendukung Pembayaran Tunggal & Rapel)
Warga mengunggah bukti transfer untuk 1 bulan atau **banyak bulan sekaligus (rapel)** dalam satu transaksi.

* **Method & Route:** `POST /resident/ipl/pay`
* **Headers:** 
  * `Authorization: Bearer <token_jwt_warga>`
  * `Content-Type: multipart/form-data`
* **Request Body (Multipart Form-Data):**
  * `billIds`: Array ID tagihan yang ingin dibayar. Format bisa berupa stringified JSON array `"[1, 2, 3]"` atau array `[1, 2, 3]` (boleh 1 elemen untuk bayar 1 bulan normal).
  * `amount`: Total nominal yang ditransfer (harus persis sama dengan `SUM(bill.amount)` dari seluruh tagihan yang dipilih).
  * `channel`: `"transfer"` (default).
  * `file`: Berkas bukti transfer (gambar JPG/PNG atau PDF, max 5MB).
* **Response Sukses (201 Created):**
  ```json
  {
    "response": 201,
    "output": {
      "message": "Bukti pembayaran 3 bulan berhasil dikirim, menunggu verifikasi Bendahara",
      "payment_id": 15,
      "bill_ids": [1, 2, 3],
      "total_amount": 600000,
      "bill_status": "waiting_verification"
    },
    "message": "Bukti pembayaran 3 bulan berhasil dikirim, menunggu verifikasi Bendahara"
  }
  ```
  > 📌 **Aturan Validasi Backend:**
  > 1. Semua `bill_id` dalam pembayaran rapel harus berasal dari Kartu Keluarga (KK) yang sama.
  > 2. Nominal `amount` wajib sama persis dengan total seluruh tagihan yang dipilih. Jika tidak cocok, request langsung ditolak (Error 400).
  > 3. Tagihan yang sedang berstatus `waiting_verification` (sedang pending) tidak dapat dimasukkan ke pembayaran baru.

## 🪙 2. Endpoint Khusus Pengurus & Bendahara (`/admin`)

### 🏢 Bagian A: Pengelolaan Periode Tagihan IPL (`bill_periods`)

#### 1. Membuat Draft Periode Tagihan Baru
* **Method & Route:** `POST /admin/finance/bill-periods`
* **Headers:** `Authorization: Bearer <token_jwt_bendahara_atau_admin>`
* **Request Body (JSON):**
  ```json
  {
    "title": "IPL September 2026",
    "defaultAmount": 200000,
    "dueDate": "2026-09-10",
    "periodMonth": 9,
    "periodYear": 2026
  }
  ```

#### 2. Mengambil Daftar Seluruh Periode Tagihan
* **Method & Route:** `GET /admin/finance/bill-periods`
* **Headers:** `Authorization: Bearer <token_jwt_staff>`
* **Query Params (Opsional):** `status` (`draft` | `published`), `year`, `month`, `page`, `limit`

#### 3. Publish Periode Tagihan — Generate Snapshot ke Seluruh Warga Aktif
Menerbitkan entri tagihan (`bills`) untuk seluruh warga aktif secara *idempotent* dengan snapshot nominal dan tanggal jatuh tempo.
* **Method & Route:** `POST /admin/finance/bill-periods/:id/publish`
* **Headers:** `Authorization: Bearer <token_jwt_bendahara_atau_admin>`
* **Response Sukses (200 OK):**
  ```json
  {
    "response": 200,
    "output": {
      "message": "Tagihan \"IPL September 2026\" berhasil dipublish untuk 120 warga aktif!",
      "period_id": 1,
      "total_bills_generated": 120,
      "summary": {
        "total_bills": 120,
        "count_paid": 0,
        "count_waiting_verification": 0,
        "count_unpaid": 120,
        "count_overdue": 0,
        "count_exempt": 0,
        "total_billed": 24000000,
        "total_collected": 0,
        "total_uncollected": 24000000
      }
    },
    "message": "Tagihan \"IPL September 2026\" berhasil dipublish untuk 120 warga aktif!"
  }
  ```

#### 4. Rekapitulasi Tagihan per Periode
* **Method & Route:** `GET /admin/finance/bill-periods/:id/summary`
* **Headers:** `Authorization: Bearer <token_jwt_staff>`

#### 5. Mengambil Daftar Tagihan Warga dalam Satu Periode
* **Method & Route:** `GET /admin/finance/bill-periods/:id/bills`
* **Headers:** `Authorization: Bearer <token_jwt_staff>`
* **Query Params:** `status` (`unpaid`, `waiting_verification`, `paid`, `overdue`, `exempt`), `page`, `limit`

#### 6. Pembebasan Tagihan / Exempt (Warga Tidak Mampu / Rumah Kosong)
* **Method & Route:** `PATCH /admin/finance/bills/:id/exempt`
* **Headers:** `Authorization: Bearer <token_jwt_staff>`
* **Request Body (JSON):**
  ```json
  {
    "reason": "Rumah kosong tidak berpenghuni"
  }
  ```

### 💳 Bagian B: Verifikasi Pembayaran IPL & Kas RT

#### 1. Mengambil Daftar Pembayaran IPL Pending (Menunggu Verifikasi)
* **Method & Route:** `GET /admin/finance/ipl-payments/pending`
* **Headers:** `Authorization: Bearer <token_jwt_staff>`

#### 2. Verifikasi Bukti Pembayaran IPL (Approve / Reject)
Bendahara menyetujui atau menolak bukti transfer IPL yang dikirim warga.
* **Method & Route:** `PATCH /admin/finance/ipl-payments/:id/verify`
* **Headers:** `Authorization: Bearer <token_jwt_bendahara_atau_admin>`
* **Request Body (JSON):**
  ```json
  {
    "decision": "approved"
  }
  ```
  *(Atau jika ditolak: `{"decision": "rejected", "rejectReason": "Nominal transfer kurang Rp 50.000"}`)*
* **Response Sukses (200 OK):**
  ```json
  {
    "response": 200,
    "output": {
      "message": "Pembayaran 3 tagihan berhasil disetujui (Approved). Status tagihan kini LUNAS.",
      "payment_id": 15,
      "bill_ids": [1, 2, 3],
      "status": "approved"
    },
    "message": "Pembayaran 3 tagihan berhasil disetujui (Approved). Status tagihan kini LUNAS."
  }
  ```
  > 🛡️ **Aturan Sistem Otomatis:**
  > - **Jika Approved**: Seluruh tagihan yang terhubung otomatis menjadi `'paid'`, dan nominal total otomatis tercatat sebagai pemasukan di `financial_ledger`.
  > - **Jika Rejected**: Seluruh tagihan yang terhubung otomatis kembali menjadi `'unpaid'` (bukan menggantung di `waiting_verification`).

#### 3. Mengambil Daftar Iuran Kas Pending
* **Method & Route:** `GET /admin/finance/kas-contributions/pending`
* **Headers:** `Authorization: Bearer <token_jwt_staff>`

#### 4. Verifikasi Iuran Kas RT (Approve / Reject)
* **Method & Route:** `PATCH /admin/finance/kas-contributions/:id/verify`
* **Headers:** `Authorization: Bearer <token_jwt_bendahara_atau_admin>`
* **Request Body (JSON):**
  ```json
  {
    "decision": "approved"
  }
  ```
  *(Atau jika ditolak: `{"decision": "rejected", "rejectReason": "Bukti transfer buram / tidak valid"}`)*

#### 5. Audit Trail Riwayat Pembayaran (IPL & Kas)
* `GET /admin/finance/ipl-payments/audit` (Query: `status`, `channel`, `billPeriodId`, `page`, `limit`)
* `GET /admin/finance/kas-contributions/audit` (Query: `category`, `status`, `channel`, `page`, `limit`)

### 📖 Bagian C: Keuangan Umum, Manual Payment, & Buku Kas RT (Ledger)

#### 1. Daftar Seluruh Pembayaran Pending (IPL + Kas Gabungan)
* **Method & Route:** `GET /admin/finance/pending`
* **Headers:** `Authorization: Bearer <token_jwt_staff>`
* **Response Sukses (200 OK):**

#### 2. Mencatat Pembayaran Iuran Manual (Cash / Transfer Langsung ke RT/Bendahara)
Digunakan saat warga membayar secara tunai atau transfer langsung tanpa upload mandiri via aplikasi.
* **Method & Route:** `POST /admin/finance/manual-payment`
* **Headers:** `Authorization: Bearer <token_jwt_bendahara_atau_admin>`
* **Request Body (JSON):**
  * **Untuk Pembayaran IPL (Mendukung Rapel):**
    ```json
    {
      "family_id": 5,
      "jenis_iuran": "ipl",
      "amount": 600000,
      "billIds": [1, 2, 3]
    }
    ```
  * **Untuk Iuran Kas:**
    ```json
    {
      "family_id": 5,
      "jenis_iuran": "kas",
      "amount": 50000,
      "category": "sosial",
      "description": "Santunan duka cita warga Blok B"
    }
    ```
* **Response Sukses (201 Created):**
  ```json
  {
    "response": 201,
    "output": {
      "message": "Pencatatan iuran IPL manual berhasil diselesaikan",
      "payment_id": 16,
      "bill_ids": [1, 2, 3]
    },
    "message": "Pencatatan iuran warga manual berhasil disimpan masbro!"
  }
  ```

#### 3. Mencatat Pengeluaran Kas RT (Expense)
* **Method & Route:** `POST /admin/finance/expense`
* **Headers:** 
  * `Authorization: Bearer <token_jwt_bendahara_atau_admin>`
  * `Content-Type: multipart/form-data` (jika unggah nota) atau `application/json`
* **Request Body:**
  * `amount`: Nominal pengeluaran (contoh: `1500000`)
  * `sourceType`: Kategori pengeluaran (`kebersihan`, `keamanan`, `taman`, `operasional_rt`, `kematian`, `sosial`, `kegiatan`, `lainnya`)
  * `description`: Keterangan pengeluaran (contoh: "Honor Bulanan Petugas Keamanan")
  * `file`: Berkas nota/kuitansi pengeluaran (opsional)

#### 4. Mencatat Pemasukan Kas RT Luar Iuran (Income)
* **Method & Route:** `POST /admin/finance/income`
* **Headers:** `Authorization: Bearer <token_jwt_bendahara_atau_admin>`
* **Request Body (JSON):**
  * `amount`: Nominal dana masuk (contoh: `500000`)
  * `sourceType`: `"donasi"`, `"subsidi"`, `"sponsorship"`, `"hibah"`, `"lainnya"`
  * `description`: Keterangan dana masuk

#### 5. Pengaturan Template Nominal IPL & Saldo Awal
> [!NOTE]
> Nilai `iplNominal` pada settings ini **HANYA BERFUNGSI SEBAGAI DEFAULT TEMPLATE** pada formulir pembuatan draft `bill_period` baru. Nilai ini tidak pernah dipakai untuk mengubah nominal tagihan aktif warga yang sudah diterbitkan.

* **Method & Route:** `GET /admin/finance/settings`
* **Method & Route:** `PATCH /admin/finance/settings`
* **Request Body (JSON):**
  ```json
  {
    "iplNominal": 200000,
    "previousBalance": 5000000
  }
  ```
